# GGM OPS v2 — 건강미 주문관리 (Phase 1)

카페24 쇼핑몰 `ggmspa`와 연결되는 Cloudflare Workers 기반 **읽기 전용 주문관리 1차 버전**입니다.

## 8차 업데이트 — 3개월 조회 · 배송 전체 백업 · 로그인 안내

- **카페24 최초 접속 UI:** Cloudflare Access가 관리자 접근을 보호하며, `/api/status`에서 카페24 OAuth 연동 상태를 확인합니다. 유효한 인증이 있으면 추가 로그인 없이 접속하고 만료/연결 해제 시에만 '카페24 연결하기' 안내를 표시합니다. 인증 비밀키·토큰은 저장소에 포함하지 않습니다.
- **3개월 조회:** 상품별 주문, 주문자·제품 조회, 판매액 그래프에 최대 92일 날짜 범위 지원. 실제 주문 API는 최대 30일로 분할 요청해 기존 제한을 유지합니다. 30일 구간 내 주문 수가 API 오프셋 한도를 넘거나 중간 오류가 나면 '부분 조회'로 표시합니다.
- **상품별 최신 구매자:** 상품 클릭 시 최근 90일 조회를 자동 시작하고, 주문일 최신순 목록으로 표시합니다. 오늘/7일/30일/3개월 빠른 기간, 직접 날짜 선택 및 해당 제품 주문 CSV 다운로드 지원.
- **판매액 그래프:** 3개월 선택 가능. 긴 기간은 주간 그래프를 기본 표시하고 일별 전환 및 막대 클릭을 통한 해당 일자 주문 조회 유지. 순매출이 아닌 결제완료 주문금액 참고 집계입니다.
- **배송 데이터 백업:** `/backup.html`의 시작일~종료일 범위에 해당하는 주문과 배송기록을 30일·8건 단위로 순차 수집. 송장번호, 배송사, 배송상태, 수령자, 배송주소를 포함한 UTF-8 BOM CSV를 사용자의 브라우저에서 생성합니다.
  - 연속 기간 백업은 날짜를 분할해 기록을 합치며 주문/배송 API 실패, 중단, 오프셋 한도 초과 시 **부분 백업**으로 분류합니다. '완료'는 모든 구간과 송장 확인이 성공했을 때만 표시합니다.
  - CSV에는 개인정보가 포함될 수 있으므로 접근권한 관리 및 보관 주의가 필요합니다. 다운로드 파일은 서버나 GitHub에 저장하지 않습니다. 과거 자료는 시작일을 직접 선택할 수 있지만 대용량 백업은 시간이 오래 걸릴 수 있습니다.
- 현재는 읽기 전용입니다. 송장 생성, 배송 상태 변경, 주문 수정, 자동 스케줄 및 장기 저장은 구현하지 않았습니다.

## 7차 업데이트 — 상품목록 다운로드 및 일별·주간별 판매액 분석

- `/products.html` : 카페24 등록 상품 목록에서 상품 선택 → 날짜 범위 지정 → 해당 상품 주문 목록 조회 → **선택 상품 주문내역 CSV 다운로드**
- `/sales.html` : **판매액·매출 분석** 신규 메뉴
  - 일별 / 주간별 결제완료 주문금액 그래프, 막대 클릭 시 해당 날짜 또는 주간 주문만 표시
  - 그래프에서 기간 선택 후 해당 주문만 CSV 내보내기
  - 조회기간: 7·14·30일 또는 최대 30일 사용자 지정
  - 카페24 주문 API를 50건 단위로 순차 조회, **500건 상한**, API 실패/중단 시 부분 조회 표시
  - 전체 주문금액이 아니라 결제완료이면서 취소 표시가 없는 주문의 금액만 참고 합계에 포함
  - **확정 매출 아님**: 부분취소/부분반품/추가환불/PG 수수료/정산 완료 여부는 반영되지 않음
- 기존 OAuth·KV·Cloudflare Access 및 주문 수정 방지 유지

## 6차 업데이트 — 로딩 · 일자별 조회 · 엑셀 내보내기

- 주문자·제품별 화면(`/explorer.html`) 접속 시 최근 30일 주문을 자동 조회하며, 조회하는 동안 회전형 로딩 표시와 진행 건수를 보여줍니다.
- 빠른 기간: **오늘 / 7일 / 14일 / 30일**
- 직접 선택: **시작일~종료일**, 과거 1년 이내·최대 30일·미래 날짜 제외. 프런트와 Worker 양쪽에서 입력 검증.
- 선택한 날짜로 카페24 주문을 순차 조회하며 최대 500건 상한은 유지.
- **엑셀 내보내기 (CSV)**: 선택한 탭(주문자 또는 제품별), 화면 검색 조건, 조회 기간, 전체/부분 조회 상태를 포함한 UTF-8 BOM CSV. Excel에서 열 수 있으나 실제 `.xlsx` 파일은 아닙니다.
- 카페24 API가 부분 실패하면 부분 조회 결과임을 표시하고 엑셀 파일에도 그 상태를 기재합니다.
- 로그인, OAuth, 카페24 주문 수정/배송 처리 코드는 변경하지 않았습니다.

## 5차 업데이트 — 주문자·제품별 주문 조회

- `/explorer.html`: **주문자 검색**과 **제품별 주문리스트** 전용 화면
- `GET /api/order-explorer?days=30&offset=0&limit=50`: 카페24 `embed=buyer,items`를 활용해 주문자와 주문상품 정보를 최소한의 필드로 조회
- 조회 기간은 최근 7/14/30일. API 페이지를 순차적으로 불러와 최대 **500건**까지 검색 및 집계
- 이름·주문번호 검색, 주문자/제품별 CSV 다운로드
- 상품번호 기준으로 제품 그룹화하고 옵션별 수량 및 주문내역 확인. 상품번호 미제공 시 상품명으로 임시 그룹화
- 이름이 같은 서로 다른 주문자는 구분 불가능하므로 '주문자 수'는 이름 기준 **고유값 수**이지 실제 개인 수를 뜻하지 않음
- API 오류/500건 상한/사용자 중단 시 **부분 조회** 표시. 완전한 전수 결과로 오인하지 않게 제한
- 고객 전화번호와 배송지 미조회 · 브라우저에서만 임시 계산 · 주문수정 기능 없음
- 새로운 API 추가 후 `mall.read_order` 권한 확인. 카페24 하위 항목 embed 응답이 누락되면 자동 집계를 중단하고 오류 표시

## 4차 업데이트 (v0.6) — 선택기간 순차 점검

- 배송관리 화면 `/shipping.html`에서 **선택기간 순차 점검** 버튼 추가
- 기존 8건 단위 API를 순서대로 호출해 최대 **400건**까지 누적 검사. 카페24 API 부하를 고려해 요청 사이 간격 적용
- 진행률 및 누적된 점검 후보 건수 표시, **중단** 버튼 제공
- 확인 필요/관찰/판정 보류 등 점검 결과 필터 제공
- 검색한 결과를 CSV 다운로드 (부분 점검/완료 여부 표시, 수식 인젝션 방지)
- 400건 상한, 요청 실패, 사용자가 중단한 경우 **부분 점검** 표시. 전체 건수를 모두 검사했다고 오인하지 않게 처리
- 개인정보는 브라우저 메모리에서만 처리하며, 새로고침하면 검사 결과가 사라짐
- 정기 자동 검사/상태 저장/알림은 아직 미구현 — 배치 실행과 저장소 설계가 별도로 필요

## 3차 업데이트 (v0.5) — 배송·누락 의심 점검

- `/shipping.html`: 배송 점검 전용 페이지, 최근 3·7·14·30일 주문을 **한 번에 최대 8건** 점검
- `GET /api/shipping-review?days=7&hours=24&offset=0&limit=8`: 카페24 주문 목록과 주문별 배송/송장 API의 실제 응답을 교차 확인
- 결제완료 후 일정 시간 이상 배송전 + 송장 미등록 시 '확인 필요' 후보
- 취소 관련 주문에 송장이 함께 있으면 '취소·송장 동시 존재' 후보
- 배송상태 미제공 또는 송장 API 오류 시 **판정 보류**; 확정적인 누락으로 표시하지 않음
- 24시간 기본 기준은 영업일·휴무일·예약배송을 고려하지 않은 예비 기준
- **자동 스캔/알림, 전체 주문 전수 검사, 자동 배송처리, CS 저장 기능은 아직 없음**
- 조회 전용 / 기존 OAuth Secret, KV, Access 구조 유지

## 구현 현황
- 실제 카페24 주문 조회 (최근 최대 30일, 페이지당 50건 / API 페이징)
- 결제 여부는 카페24 `paid` 필드 기준으로 집계 (`T`: 결제완료, `F`: 결제대기, `M`: 부분결제)
- 주문번호 클릭 시 상품명·옵션·수량·품목별 배송상태 및 송장정보 **읽기 전용 상세 조회**
- 현재 페이지 주문번호 검색, 결제상태 필터, 기간 선택, 목록 CSV 내보내기
- 주문 상태를 기본 주문목록에서 제공하지 않는 경우 `상세 조회`로 표시 (임의 상태 집계 없음)
- API 연결 상태, 응답 오류/빈 목록 표시
- OAuth 최초 연결 및 토큰 갱신. 기존 KV의 토큰 키 재사용
- 개인정보 최소화: 주문번호, 일시, 상태, 결제금액만 반환
- 주문 수정/송장 등록/CS 저장/자동 동기화는 **아직 미구현**

## 배포

1. Cloudflare > Workers & Pages > 기존 `ggm-ops` > Settings > Builds > Connect 에서 `jyhome1228-cyber/ggmprogram` 연결
2. Production branch: `main`, build command: `npm run deploy` (또는 Cloudflare 기본 Wrangler deploy 설정), root directory: `/`
3. Worker 이름이 `ggm-ops`인지 확인
4. 기존 `CAFE24_CLIENT_ID`, `CAFE24_CLIENT_SECRET` **Secrets**, `GGM_AUTH` KV 바인딩 유지/확인
5. **Cloudflare Access 전체 Traffic 보호가 유지되는지 검증**. 이 Worker는 네트워크 경계의 Access 정책을 신뢰하므로 공개 배포 금지.
6. 배포 후 `https://ggm-ops.planus253.workers.dev/`에서 조회 테스트

Cloudflare 연결 전에는 GitHub에 코드만 반영되며 운영 Worker에는 즉시 적용되지 않습니다. 기존 수동 배포 Worker를 덮어쓰기 전에 KV/Secrets/Access가 연결된 상태인지 점검하세요.

## API
- `GET /api/status`: 연결 여부
- `GET /api/orders?days=30&offset=0&limit=50`: 주문 목록. 날짜는 KST 기준.
- `GET /api/orders/{order_id}/items`: 주문 상품 상세 (주문 읽기권한)
- `GET /oauth/start`: 재연결
- `GET /oauth/callback`: 인증코드 수신 및 토큰 저장

**보안:** Client Secret, 토큰, 고객 개인정보는 GitHub에 저장하지 않습니다. 개발 프리뷰를 공개 배포하지 마세요. OAuth KV는 최종 버전에서 D1/Durable Objects 기반 직렬화 및 장기 모니터링 보강 예정입니다.
